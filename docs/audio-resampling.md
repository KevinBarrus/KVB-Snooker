## 边界与来源

- 只从官方原声比赛音轨取样，不使用录屏、BGM混剪、自动配音或平台额外DRC音轨。
- 下载工具为官方 yt-dlp 独立程序，放在忽略的 `.cache/audio-acquisition/`，不新增项目依赖。
- 下载音轨保持压缩流；切割时直接从源文件解码为48kHz PCM24 WAV。检查时的临时解码不回写源文件，不形成有损转码链。
- 不降噪、不归一化、不压缩、不EQ、不淡入淡出。视频仅用于判断碰撞类型与相邻事件，最终边界由音频确认。
- 来源URL、发布者、格式ID、下载方法、源SHA-256、裁剪命令均留证。ffprobe无法证明上游压缩代数；标称128kbps AAC可能报告127999bps，只容许这一整数舍入差。
- 原片及输出媒体不进Git。`local-audio-new/` 与 `.cache/` 均忽略。脚本输出必须使用新目录，已有目录直接拒绝。

## 批量切割

```sh
npm run audio:cut -- .cache/audio-acquisition/cuts.json .cache/audio-acquisition/new-batch
```

JSON路径相对于时间戳清单所在目录；所有时间为源音轨上的秒数，不是视频播放器四舍五入后的整数秒。

```json
{
  "version": 1,
  "sources": [{
    "id": "wst-match",
    "file": "match.m4a",
    "url": "https://www.youtube.com/watch?v=SOURCE_ID",
    "title": "官方录像标题",
    "uploader": "WST",
    "acquisition": "yt-dlp下载原始音轨，记录格式ID和语言"
  }],
  "clips": [{
    "sourceId": "wst-match",
    "startSeconds": 10,
    "impactSeconds": 10.12,
    "endSeconds": 10.72,
    "nextEventSeconds": 11.0,
    "group": "ball",
    "intensity": 0.75,
    "note": "填写画面证据、力度判断与不确定性"
  }]
}
```

上例仅说明结构，不代表真实可用球局。`nextEventSeconds`未知时可省略，报告会明确待人工检查。大力撞击后只能保留350～500ms时，必须填写`shortTailReason`，不能静默降低要求。

`group`只允许cue-low / cue-mid-low / cue-center / cue-high / ball / pocket-clean / pocket-jaw；intensity只允许0.1 / 0.3 / 0.5 / 0.75 / 1。杆法和力度是画面分类标签，不是从响度反推的真实物理参数；不明确的标签须在备注登记并由用户确认。

## 数值门槛与人工判断

| 检查 | 标准 |
|---|---|
| 前导 | 撞击前100～150ms |
| 后导 | 0.1/0.3至少250ms，0.5至少350ms，0.75至少450ms，1.0至少500ms；登记理由后1.0可降到350ms |
| 背景 | 撞击前100ms，所有声道合并RMS≤−50dBFS |
| 起音 | 撞击后50ms峰值相对上述背景RMS跃升≥15dB |
| 尾部 | 最后50ms合并RMS≤整段峰值−45dB |
| 趋势 | 最后50ms分成5个10ms窗口；相邻窗口允许上升3dB，低于−70dBFS不判断上升 |
| 峰值 | ≤−1dBFS；逐声道连续3个同号近满量程采样视作削顶 |
| 下一事件 | 已知时，裁剪终点至少提前20ms |

尾部趋势不是采样点单调下降，也不能证明其间没有其他事件。浮点/整数采样与帧数舍入仅容许1～2采样误差，不放宽声学阈值。

输出为扁平命名，例如`ball-075-01.wav`。数值未通过的文件放`rejected/`，不混入根目录候选；`manifest.json`记录完整参数、指标、原因和命令，`audit.md`给出统计、缺口和试听清单。所有数值通过候选仍为`manualStatus=pending`，工具不自动授予“人工合格”。

人工验收只需判断：是否混入解说/咳嗽/其他碰撞，起音和尾音是否完整，分类/力度是否合适。允许全部否决，禁止为凑数量将不确定素材塞入合格集。
