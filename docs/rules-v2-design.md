# 规则完善与双人规则测试

2026-10-26用户授权分步实施。镜头已验收；自己的出杆使用V观察模式，AI/未来远端对手球权完全自由旁观。

## 边界与事实来源

- 正式规则共享于人机、双人测试与未来联机；不维护测试专用判分分支。
- `docs/spec/05-规则引擎.md`和PCOL L12703-12822保留原作事实；新增规则以WPBSA 2024-25规则册为依据，不伪称原作实现。
- 官方来源：https://wpbsa.com/wp-content/uploads/2198_WPBSA-Rulebook-2024-25.pdf 。主要对照§2.12/17、§3.3-8/10-14。
- 自由练习保留65535哨兵、随意击球和原有复位行为。物理求解与摄像机算法不改。
- 用户确认Miss单独定稿；本轮不把MISS_TARGET直接升级为FOUL AND A MISS，不提供无条件原位重打。

## 施工单元

1. 独立测试入口：标准开局、最后一红、清彩；两名本地玩家；加载/完整重置；正式构建排除。
2. 基础规则边界与终局：合法/犯规计分、清彩复位、最后黑球和平分决胜。
3. 提名和普通犯规选择：明显目标自动识别并显示，歧义/翻库手选，出杆前冻结；非犯规方选择接手或让对手当前位置继续。
4. 贴球与自由球：打离合法贴球满足首触；打离非目标贴球仍需击中合法目标；自由球资格、提名、计分和复位。
5. Miss和复位重打另行设计。复位只恢复杆前台面及相应规则状态，已罚分不撤销；与测试的完整重置完全分离。

每个单元跑全量test/typecheck与对应浏览器回归，更新模块章程，独立提交推送。

## 测试工具与装配契约

- `src/devtools/`只允许由开发入口动态加载。`import.meta.env.DEV`控制生产排除，`VITE_RULES_TEST=0`关闭本地入口。正式核心不依赖devtools。
- `GameMode`仍只有practice/single-play。GameSession新增可选GameOptions：players指定本地/AI席位；setup指定完整FrameSetup。不是新增正式游戏模式。
- FrameSetup包含所有球的index/x/z/active、ballOn、inHand、playerIndex及两侧初始得分；核心先验证完整性再使用。初始化/重置清空本杆结果、累计统计、单杆、历史最高单杆与回合数；球姿态回到预设初始状态。
- BrowserGame.setMode第三参数接收GameOptions；同一入口清理出杆、摆球、旧回放、HUD提示、控制器状态。忙碌/回放中拒绝加载，不先改核心。
- PersonController保留对象身份，playerIndex表示当前控制的席位；locallyControlled区分本地输入与AI。球权交给本地席位时重绑human.playerIndex；ShotController按本地控制标志决定输入锁和自动观察，不按编号0判断。
- 测试入口仅提供模式选项、测试球局下拉、加载、重置按钮；普通模式不显示测试控件。预设改变不立即破坏当前局面；完整重置恢复当前已加载预设。
- 标准开局22球、红球目标、D区手中球；最后一红为1红+6彩+母球，目标红；清彩为6彩+母球，目标黄。普通预设双方0分、玩家1出杆。

## 规则状态与交互

- 规则层判断；流程层计分/等待选择/换人；UI仅展示并提交命令。待选择时禁止下一杆，重复选择不重复罚分。
- 提名独立于阶段ballOn，禁止借用65535表达自由球。自动提名只推断意图，不能用实际首碰倒推意图。
- 自动提名按母球与球杆方向、目标角尺寸、遮挡及歧义判断，不受辅助线1.6米限制。界面显示当前目标，手动提名优先，出杆开始固定。自由球与进红后贴彩球需要显式提名。
- 贴球记录杆前接触，区分合法目标与非目标；不得将静止接触误算新首碰，不凭末位置微小漂移判推杆。
- 自由球是犯规后满足斯诺克条件的选择，不以miss为前提；用母球出发的合法接触边界判断，不读取摄像机。
