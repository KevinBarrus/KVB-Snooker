# 斯诺克 900：规则与基础时钟

状态：2026-11-07 整理后的现行需求。核心与浏览器已有实现，具体差异和验收状态只在 [项目状态](project-status.md) 维护。本文不声称 900 已完整验收。

## 1. 范围与依据

900 是用户批准的项目扩展，不是 PCOL 原作转写。规则与对局方式独立，当前用于人机和双人规则测试；正式联机由联机设计接入，自由练习不施加 900 规则。

已查来源（沿用 2026-11-02 的核实记录，本轮未重新访问）：[900 官方简介](https://snooker900.tv/learn-snooker-900)、[WPBSA 规则入口](https://www.wpbsa.com/rules/)、[2024–25 规则册](https://www.wpbsa.com/wp-content/uploads/2198_WPBSA-Rulebook-2024-25.pdf)。官方简介确认主要玩法，但不足以证明所有细节；Shoot Out 附录只是对照，不把其局时、罚值或程序当成 900 官规。

以下专门罚值、蓝球程序、严格截止和起表方式采用用户已确认的游戏约定。原作规则事实仍由 spec/05 保存，经典扩展见 [经典规则](rules-v2-design.md)。

## 2. 基础时钟

| 阶段 | 整局 900 秒 | 本杆 20 秒 |
|---|---|---|
| 初始加载、台面尚未准备好 | 未启动 | 未启动 |
| 进入比赛、准备好且允许操作 | 立即启动 | 立即启动 |
| 思考、提名、摆球、确认、瞄准、尚未触球动画 | 继续 | 继续，不补时 |
| 已接受实际触球、球运动 | 继续 | 停止 |
| 球停后的规则结算与必要归位 | 继续 | 停止 |
| 全部完成，下一杆允许操作 | 继续 | 重置并启动 |
| 局时归零且有已触球的一杆 | 固定 0，等完整结算 | 不开启新杆 |
| 终局 | 停止 | 停止 |
| 蓝球决胜 | 固定 0 | 每次独立计时，准备完成即启动 |

按 W、Space 或开始动画都不是触球；首杆不等玩家进入瞄准才起表。不能只看母球停止，不能等待相机起身结束才开启下一杆。

时间由核心消费外部单调时间输入，不用物理 evolution、快进步数、渲染帧或回放倍率代替。界面只显示快照。浏览器失焦和菜单不自动暂停；未来正式暂停是已批准的独立例外，暂停/暂存及掉线规则只在 [生命周期](match-lifecycle-design.md) 定义，目前不能把该设计当作现有按钮已生效。

同帧跨触球和截止时按事件实际顺序处理，不能先扣整帧再误判提前触球。后台长间隔不得当巨大物理 dt。触球必须严格早于截止；恰好截止算到期。两表同刻到期且尚未触球时优先终局，不追加超时罚分。

## 3. 判罚与终局

- 复用红彩顺序、合法首碰、提名、贴球和基础计分归位；增加时间犯规、碰库义务、全台手中球及蓝球决胜。
- 无进球且没有有效新碰库时追加专门犯规；不额外限定必须在首碰之后碰库。静止贴库不能算已完成义务。
- 超时与未碰库的最低罚分均为 4，目标值更高取更高值；彩球待提名时按 7。与其他违规合并取应罚最高值，不重复累加。
- 正常犯规结束当前单杆，对方获得全台手中球；不进入经典自由球提名、让对方继续或 Miss 菜单。极端无合法路线也不暗中赠送经典特殊权利。
- 全台手中球指移动母球，不是任意彩球替代目标的自由球。最终摆放区域仍由核心校验。
- 仅剩黑球时，局时未尽的犯规仍罚分、必要归位、保持黑球目标并换人，不能因经典末黑逻辑提前判胜。合法清台或局时到期结算后比较比分，平分进入蓝球决胜。
- 截止前已触球的杆完整运行，所有合法得分及罚分入账后才判断终局；不得按归零瞬间旧比分判胜。

超时取消旧预备、动画与 AI 任务，不施加冲量，也不另模拟一个无首碰空杆再次罚分。同一截止只裁决一次。

## 4. 碰库证据与摆球

模拟器独立观察真实有效接触，sidehard/sidesoft 作为库/袋角，ground/pocket/tunnel/end 不计碰库义务。证据不能来自是否播放音效、渲染接触或单纯 isSS=false；预测不得写入真实杆证据，观察不得改变求解次数或公式。

开局与蓝球决胜限 D 区，正常犯规后放开合法台面支撑区。区域、有效高度、球半径、库面/袋口和其他球间距由核心验证。鼠标手势、光环、P/W/ESC 与最终落点语义统一见 [摆球设计](cue-ball-placement-design.md)，不在本文件复制键位表。

AI 也使用相同放置与确认命令，必须先放好母球，再按实际位置激活瞄准和搜索。搜索、思考和触球前动画都消耗出杆时间，不能沿用摆球前旧锚点或绕过时钟。

## 5. 蓝球决胜

蓝球放原点，母球从 D 区击打，本局非开球方先打。每次尝试使用独立出杆时间，双方同等尝试次数后比较合法直接进球，平手继续；先手进球不能跳过后手对应尝试直接获胜。

母球摔袋、超时或其他犯规算本次失败，不追加普通得分或全台手中球。正常比分保持原值，决胜次数、进球结果与胜者单独保存。

直接进球允许目标袋弧面，不允许先碰其他库面。当前几何判断使用近似，用户曾报告同进误判，排查状态见项目状态；不以已有测试通过代替此问题已修复。

## 6. 界面与外观

局时只显示分秒；已确认的出杆 UI 需求是 20 格绿色栏，每经过一秒少一格，实际剩余不超过 3 秒变红，0 秒为空，可辅以数字。触球后保留本杆余量，下一杆开始才重置。当前代码与此需求的差异见项目状态 R01，整理文档不改变冻结接口或自行批准新颜色。

显示当前玩家与摆球计时中、球运动、等待结算和蓝球阶段；不显示旧“摆球暂停”。临时犯规提示遵守 [UI 设计](ui-design.md)，关闭提示不改变裁决。

红点是母球材质内部的六个球面图案，使用局部坐标或 UV，与白色部分共享光照和反射，不使用凸起球、悬浮圆盘或独立自发光贴片。尺寸、质量和物理不变；显示及回放消费真实四元数，不根据位移伪造滚动。

900 活跃局内禁用会暂停真实对局的上一杆回放，终局保留四分之一慢放。AI 球权自由旁观，不能为计时或材质改动调整既有镜头手感。

## 7. 接口与验收

正式接口只在 [架构 §4.7](architecture.md#47-斯诺克-900设计阶段2026-11-02) 维护。核心负责裁判，装配提供时间并连接控制器/AI，UI 读快照，render 读姿态，测试工具只注入正式配置。

验收至少覆盖：首杆立即起表；摆球不补时；实际触球与截止前/同刻/后；低帧率；球未全停不重置；超时取消；AI 摆球锚点；900 末黑犯规继续；同等次数蓝球决胜；切换经典无残留；真实红点旋转和回放。
