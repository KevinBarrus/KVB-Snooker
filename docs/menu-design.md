# 游戏菜单：导航与装配

状态：菜单已有本地实现；账号、正式房间及若干入口仍是占位。本文维护菜单导航和装配边界，不定义比赛权限或规则。视觉原则见 [UI 章程](../src/ui/AGENTS.md)。

## 1. 导航

进入网页显示 AI 对战、双人对战、练习、我的、操作指南五个入口；进入对局后收起，左上角保留菜单按钮。局内菜单是 UI 叠层，展开不暂停物理、AI 或对手。

AI 对战选择规则与难度；双人入口提供创建和加入；练习区区分自由练习、预设球形和自建球形；我的承载账号、统计、好友及后续高光。入口的可用性服从 [账号与游客](accounts-and-guests-design.md)，不在菜单另存权限表。

指南的内容、首次弹出和关闭方式也由账号设计维护。× 只关闭菜单或指南，不默认结束比赛。

## 2. 当前占位与正式接入

| 入口 | 当前本地版本 | 正式产品接入位置 |
|---|---|---|
| AI 对战 | 规则/难度必选，装配本地 GameSession | 账号权限与在线成绩设计 |
| 创建双人 | 保存菜单赛制配置，进入本地双 USER；局数不等于已实现整场 | 联机设计的服务端建房、准备和整场状态 |
| 加入双人 | 任意非空文本可进入本地测试，不能验证真实房间 | 服务端查房、身份及席位校验 |
| 暂停 | 预留信号，不能视为已暂停 | 生命周期的正式暂停 |
| 重新开始 | 本地重建对局 | 正式联机改为双方同意重摆，不直接 setMode |
| 操作指南 | 已接入键盘/练习说明弹层，主菜单与局内菜单均可打开 | 指南内容由 UI 维护；账号设计只维护首次弹出与权限 |
| 账号 | 空操作或提示占位 | 账号与游客设计完成后接入，不宣称可用 |
| 十种预设球形 | 已接入真实练习流程；点击卡片先选经典/红点母球 | 见[练球球形设计](practice-shape-design.md) |
| 我的球形 | 已接入创建/编辑/回收站与自建练习 | 见[我的球形设计](my-shapes-design.md)；存储仅本机 localStorage |

以上描述现有缺口，不是要求正式版本继续接受任意房间码或保留无反馈按钮。开发双人测试必须与正式联机入口分开。

## 3. 界面与输入

模式卡片、难度选择和主按钮应形成清楚的操作顺序；缺少必填项时主按钮禁用。加入房间时非空校验只检查输入，只有服务端成功才可进入比赛。

房间设置变化使旧建房结果或准备状态失效，如何处理由联机流程决定。复制按钮只复制已获得的房间码，不伪造 ID。退出对局按生命周期请求暂存或明确认输，不能只返回菜单后丢弃对局；练习模式退出前必须先弹出确认，取消不改变对局。

局内操作面板保持 ×、键盘焦点和返回层级可预测，不遮挡玩家必须处理的规则选择。菜单拖动或点击不能透传成一次摆球或击球。

当前皮肤的颜色、尺寸和控件结构以 CSS/视图实现维护，用户不满意的样式不冻结为宏观原则。早期皮肤稿见历史存档，后续可在不改业务流程的情况下替换。

## 4. 模块边界与验收

`game-menu.ts` 维护零 DOM 导航状态，`game-menu-dom.ts` 渲染并转发意图，app 装配根连接真正功能。UI 不直接持有数据库、WebSocket 裁判或核心可变状态。

验证层级切换、必填状态、关闭与焦点、不同模式的操作入口，以及服务端拒绝时仍留在正确界面。两客户端准备和重摆须由联机验收，不用菜单单测冒充完成。
