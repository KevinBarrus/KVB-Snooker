# 双人联机：房间、权威对局与通信

状态：2026-11-06 产品范围已确认，以下服务端结构为拟实施方案。当前双人规则测试仍是本机轮换控制，不能视为已经具备联机能力。

## 1. 第一版范围

登录玩家创建房间，选择经典或 900、比赛局数，通过房间码或链接邀请朋友。对手加入后看到相同设置，双方准备后开始。游客不能加入比赛。第一版不做公共匹配、天梯积分或跨区匹配。

比赛采用既有长局制选择，赢下规定局数才赢得整场比赛。单局与整场必须是不同状态对象，不能把每次 `GameSession` 终局都当成整场胜利。

开球按已确认规则逐局轮换，人机长局制首局玩家开球、下一局 AI 开球；一局定胜负的正式双人比赛随机决定先手，并把结果保存。长局制双人首局的选先方式需要在房间流程落地时显式展示，不由刷新页面重新抽签。争黑由本局非开球方先打，900 蓝球程序沿用其现有设计。

摄像机完全属于各玩家自己的客户端。不是本人球权时可以自由观察，不启动本人的 V 跟随模式；轮到本人后恢复其个人偏好。一个玩家的相机、鼠标、音量不能影响另一方。

## 2. 分层

采用 Node 服务端运行已有无 DOM 的 core，WebSocket 传递对局命令和状态，PostgreSQL 保存账号、比赛及统计，媒体使用对象存储。具体目录和公开接口在实施前写入 `architecture.md`，本设计不擅自增加现有 Simulator 的公开签名。

| 层 | 职责 |
|---|---|
| core | 物理、单局规则、确定的状态转移；不引入网络、数据库或 DOM |
| 服务端对局服务 | 身份与席位、房间、时钟、命令校验、整场状态、持久化 |
| 客户端装配 | 把本地意图送往服务端，把权威结果交给显示与控制器 |
| render / controller / ui / audio | 显示、输入、镜头和声音；不自行裁决正式分数 |

核心继续服务练习、人机和测试；网络分支不得散落到物理、规则和每个 UI 控件中。不要为联机复制一套斯诺克规则。

## 3. 命令与状态

客户端提交“希望出杆、放球、提名、选择判罚”等意图，不提交“已经得分”或直接覆盖整台球的位置。服务端验证身份、席位、球权、当前阶段、有限数值、力度和触点范围，再调用核心。

每条改变状态的命令携带唯一命令 ID 和预期的比赛、局、回合版本。每个房间顺序处理命令；重复请求返回已保存的同一结果，过期请求明确拒绝。收到确认不明时可以重试，不能因此出两杆、罚两次或恢复两次。

服务端验证放球最终落点；客户端绿色光环只是预览。具体交互见 [摆球设计](../../cue-ball-placement-design.md)。服务端拒绝时客户端恢复权威位置并解释原因，不能静默保持另一份球位。

900 的触球时刻由服务端认可的出杆流程决定，不能信任客户端任意回填的时间戳。准备出杆、播放动画和实际触球之间的协议必须单独测试；不能把收到 Space 的时刻直接当成杆头触球，也不能因为网络晚到而允许事后伪造压哨。延迟补偿若要引入，须先明确上限与验证方法，首版不暗中授予额外时间。

## 4. 运动同步与版本

服务端推进真实物理和规则；客户端可以平滑显示或预测，但最终服从权威状态。权威检查点包含位置、速度、自转和必要规则状态，不能只同步 XYZ 而丢失红点母球的朝向。

不承诺不同浏览器、引擎版本和调度下逐位相同。命令加种子有利于复现，但不自动等于完整确定性；显示轨迹、状态核对和纠偏需要实际验证。物理固定步长与比赛真实时钟分开，服务端卡顿后不能用一个巨大 dt 推物理。

正式比赛锁定规则版本、物理参数、引擎版本和必要资产版本。用户本地修改台泥或库边参数不能改变服务器比赛；暂存后恢复继续使用兼容版本，不能悄悄换新参数。

当前随机源和部分物理配置有模块级状态，当前 AI 搜索还受执行调度影响。多房间前必须检查共享状态，确保房间之间不会串随机序列或调参。记录已采纳的 AI 出杆，不依赖恢复时重新思考得到同一杆；具体采用房间实例隔离还是工作线程，在服务端原型中验证后决定。

## 5. 语音

网页可以通过 WebRTC 实现双方通话。房间服务负责鉴权和信令，音频走 WebRTC；需要 HTTPS、用户主动授权麦克风，以及覆盖目标网络的 STUN/TURN 服务。不能假设两个家庭网络总能直连。

第一版语音作为独立单元：主动开启、静音、对方音量、说话指示和连接状态。按键说话的键位在输入冲突检查后确定。语音失败不应中断击球或重连，默认不录音，也不把语音写入高光。

首批测试大陆两种不同网络，包括无法直连而走 TURN 的情形；海外部署以后再扩展。TURN 流量和服务凭证属于服务端运营配置。

## 6. 验收

- 两个独立登录客户端能完成经典和 900 整场比赛，分数、球权、时钟与终局一致。
- 非当前玩家无法出杆或改位；旁观镜头自由，下一杆本人观察恢复。
- 重复、乱序、过期、越权和非法数值命令不会破坏状态。
- 一方网络慢或重新连接后，恢复权威球位、自转、判罚选项与剩余时间。
- 两个房间并行运行不互相影响；修改客户端调参文件不能改变正式结果。
- 语音断开不影响比赛，静音和未授权麦克风时不会偷偷采集声音。
