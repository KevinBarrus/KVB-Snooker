# 两人内测：可玩经典联机

状态：2026-11-11 已实现，待人工远程双机验收；自动验证记录见项目状态。用户批准将内测部署与身份交给 Deepseek，第三步由 GPT 并行实现。产品行为引用 multiplayer-design.md、rules-v2-design.md、cue-ball-placement-design.md；本文件维护此次接线范围与交接。

## 分工

Deepseek 负责身份/数据库/部署/登录及本地试玩入口。GPT 负责 src/net、src/server 的联机房间与对局接线、新增 app-net 装配和联机 UI。共同文件只作局部改动；不覆盖他人的修改。物理调参、核心规则、镜头与出杆插值算法不改。语音、长期暂存、120秒掉线裁决与联机900留后续。

## 交付顺序

1. 经典规则操作：摆球、提名/自由球、犯规接手/让对手继续/Miss复位。所有操作由权威GameSession校验，版本与命令去重复用。观看方无修改权限；已准备出杆、运动和暂停时拒绝修改。
2. 对局显示：复用本地比分牌、力度条、规则选择、贴球/犯规通知和已有音频后端；只消费权威快照和事件。网络诊断默认收起，开发参数可开启。声音按服务器运动时间与客户端显示时间对齐，不从客户端预测触发。
3. 房间：服务端创建短房间码，加入不存在房间不得自动建房；两位稳定身份各占一席；同账号不能占两席，第三人不能进入；资源加载后双方准备才允许开球。赛制只允许经典及既有局数。用户由身份适配器提供，不相信客户端自报ID或席位。
4. 浏览器创建/加入/准备入口与生产身份接线，使用实际身份服务完成双账号验收。身份尚未交付时使用仅测试注入证明房间行为，不将其冒充公网鉴权完成。

## 依赖与身份交接

身份实现不在本模块复制。需要 Deepseek 提供可信会话解析入口（稳定 userId、显示名、会话失效语义）；服务端通过注入调用，不让房间依赖账号SDK或数据库。浏览器同源连接；生产握手不能回退到开发令牌。资源和正式入口仍由装配负责。已收到的适配决定见下文。

## 验证

纯命令与真实GameSession验证非法/重复/旧版本/错误席位，摆球最终落点与重复移动、提名与自由球、Miss保留罚分；真实WebSocket验证两端一致。浏览器验证创建/加入/双方准备、正常击球、比分/单杆/力度、暂停、规则选择、摆球重锚及对手自由观察、声音显示时序。全量test/typecheck及已有test:net回归后分单元提交。未接真实身份、未做实际远端双机验收的部分如实标注。

## 身份接线决定（2026-11-11）

Deepseek已提供 [SessionVerifier](identity-session-verifier.md)。房间独立进程通过内网HTTP端点校验Cookie，调用方只消费userId/displayName/role；不导入身份SDK或数据库。玩家WebSocket与HTTP均限制同源，握手、命令及每秒心跳校验会话；撤销失败/服务异常关闭连接。传输异步认证与物理tick分离，队列有界，不因数据库等待冻结权威球运动。

GameMenu的双人按钮由装配回调导航到真实创建/加入页；该页与`?room=`始终要求登录。房间由服务端生成，规则设置在创建时固定。一个账号同时保留一个房间资格，同账号不能占两席或用第二连接挤占席位。等待/终局允许离开，进行中不提供单方删局。长期保存另行实现。

声音来自权威Simulator.onImpact，显示游标到达事件时播放一次；过期碰撞不集中补播。新增音效事件不提高球位快照频率。不调整素材、DSP、物理或既有镜头轨迹。

同时准备恢复暂停可能遇到版本竞争；仅对同一attempt且仍paused、本人尚未ready的pause-ready意图重新生成命令重试。出杆、摆球和规则选择不自动套用到新版本。

部署与人工步骤见 [部署接线](multiplayer-player-deployment.md)。真实远程双机、声音听感和网络质量仍须用户验收，不能用本机软件渲染的FPS推断玩家硬件性能。
