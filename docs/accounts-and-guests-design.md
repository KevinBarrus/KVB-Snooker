# 账号、游客与进入游戏的流程

状态：2026-11-06 已确认的产品范围，待实现。工程方案为后续施工依据，不表示服务端或登录系统已经存在。相关设计见 [联机实施计划](multiplayer-implementation-plan.md)。

## 1. 发布方式

保留网页试玩，让玩家打开链接即可体验。后端按网页和未来桌面客户端共用的方式建设，账号、比赛、统计和高光不绑定浏览器本地存储。第一版不做桌面打包、Steam 接入或离线成绩上传。

第一版正式比赛要求在线，包括会计入成绩的人机比赛。断网不能继续在本地积累一份可以直接上榜的成绩。以后支持离线时，需要另行定义本地记录、同步、防重复和可信度，不能把它当成简单补传接口。

首批服务大陆玩家，之后扩展地区。先部署一个区域，不提前建设跨洲数据库同步；账号身份不绑定部署区域。

## 2. 功能权限

| 功能 | 游客 | 注册并登录的玩家 |
|---|---|---|
| 经典 Easy 人机 | 可以 | 可以 |
| Normal / Hard 人机 | 不可以 | 可以 |
| 斯诺克 900 | 不可以 | 可以 |
| 自由练习 | 不可以 | 可以 |
| 好友联机 | 不可以 | 可以 |
| 浏览排行榜、公开个人成绩 | 可以 | 可以 |
| 浏览公开高光 | 可以 | 可以 |
| 保存比赛、记录个人成绩、收藏高光 | 不可以 | 可以 |

双人规则测试是开发工具，不是游客或正式玩家的联机入口。正式构建继续排除该工具。

受限入口可以展示，点击时引导登录，不能伪装成已经创建成功的比赛。服务端必须独立检查权限，不能只依靠前端隐藏按钮。

## 3. 游客身份与指南

未登录时生成本次访问使用的临时游客 ID。刷新、关闭后重新进入得到新 ID；同一次访问内切换菜单不更换。游客没有可恢复的账号档案，不保存个人比赛成绩，也不把游客历史补记到注册账号。

游客首次进入本次访问时展示指南，分为三个部分：

1. 游客与注册玩家可用功能，提供登录、注册入口。
2. 操作指南，包括瞄准、出杆、观察、摆球和菜单。
3. 游戏规则，区分经典与 900，并说明游客当前只能体验经典。

指南始终提供 ×，允许立即关闭，不要求看完。菜单内可以重新打开。关闭指南只是结束阅读，不自动开始计时比赛；玩家明确开始对局、台面准备就绪后才启动对局流程。

## 4. 注册玩家资料

第一版采用邮箱和密码，包含邮箱验证、登录、退出和密码找回。手机号绑定暂缓，Steam 身份关联留到桌面发行阶段。

账号使用稳定的内部用户 ID；邮箱、昵称和外部平台身份都不能替代它。改昵称不改变比赛归属，也不重新生成榜单记录。是否允许重名及昵称字符限制在账号实现时固定；搜索结果需能区分不同用户，不能靠昵称判断是否为同一人。

个人资料支持头像、昵称、国家或地区。国家或地区是用户自选展示项，不作为身份验证、网络路由或强制定位依据。邮箱与手机号不出现在公开主页和排行榜。

头像上传由服务端限制格式、尺寸和体积，解码并重新生成展示图片，清除无关元数据；媒体进入对象存储，数据库保存归属和引用。不得让客户端任意指定对象路径或覆盖他人头像。

密码使用成熟实现提供的安全哈希，不自行设计加密算法。邮箱验证、找回和登录需要限流；令牌应有期限、单次使用规则和撤销能力。网页会话与未来桌面凭证共用身份服务，具体传输方式在接口施工阶段确定。

## 5. 数据边界

公开主页展示比赛统计与主动公开的高光。私人高光、暂存比赛和账号凭证仅本人及必要的对局参与者可访问；知道资源 ID 不等于获得访问权限。

账号删除、昵称审核、上传额度等运营政策不在本轮定死。上线前必须明确并在界面如实显示，不能因此承诺无限媒体容量。基础设施诊断日志与游客的个人成绩档案是不同数据，不把“游客不记成绩”解释成系统完全不能记录故障。

## 6. 验收

- 游客刷新后 ID 改变；同次访问切菜单不变；关闭指南不受阻。
- 游客只能建立经典 Easy 比赛；直接调用受限接口同样被拒绝。
- 注册登录不会把游客成绩混入账号；退出后无法继续操作旧账号比赛。
- 修改昵称、头像、国家或地区不影响用户 ID、比赛和成绩归属。
- 未登录用户能浏览榜单及公开高光，不能读取私人内容。
- 网页请求中不包含数据库凭证、邮件服务密钥或其他长期服务端密钥。
