# 首版联机实施计划

更新：2026-11-07。本文只管理工作顺序、依赖与交付门，不复制产品设计。设计入口见 [文档导航](README.md)，实际完成状态及待决项见 [项目状态](project-status.md)。

## 1. 交付边界

先完成好友邀请式联机，复用当前网页和正式核心；后端按未来桌面共用设计。Steam 打包、公共匹配、离线上榜和 MP4 导出不在首版范围。既有摆球修复由用户报告已完成，本轮不重新施工或代替人工验收。

## 2. 分步交付

| 单元 | 内容与交付物 | 前置条件 | 验收门 |
|---|---|---|---|
| A 文档与契约准备 | 明确领域边界、整理现有设计、列出协议及持久化提案 | 当前需求 | 权威来源明确，未定事项不伪装已批准 |
| B 核心整场基础 | 单局/整场/尝试身份，完整状态检查点，暂停与恢复能力，必要统计事件 | A；相关接口登记 | 本机长局制及经典/900回归，不引网络进 core |
| C 身份与服务基础 | 邮箱账号、游客权限、数据库迁移、服务端目录与测试环境 | A | 独立账号隔离，受限接口服务端拒绝 |
| D 最小权威双人 | 房间、准备、命令确认、运动同步、经典一局唯一结果 | B/C；协议原型验证 | 两个真实客户端、弱网和重复命令，两个房间互不污染 |
| E 完整生命周期 | 长局制、900、协商重摆/暂停、暂存、重连与故障恢复 | D；相关产品待决项定稿 | 持久化故障测试、900触球截止、完整恢复 |
| F 成绩公开 | 八类整场胜负、个人统计、累计榜单 | E；权威事实与计时事件 | 幂等重建，预设/游客不上榜 |
| G 高光 | 逐杆归档、手动收藏、自动里程碑、串联、隐私与回收站 | D起准备归档，E/F完成正式来源验证 | 不丢前杆，访问控制与删除引用一致 |
| H 语音 | 房间鉴权信令、授权、静音、连接与释放 | D | 直连/中继、拒绝麦克风、语音失败不影响对局 |

B 与 C 有独立部分，但协议、身份及比赛标识要先共同约定，不让两边分别发明不兼容概念。表格表示依赖，不要求使用多代理或同时编码。

统计起止事件与逐杆归档能力应在基础对局阶段留下真实事实；F/G 是开放产品功能的阶段，不意味着到那时才开始记录必要数据。语音可按内测优先级调整，不阻塞基础比赛验收。

## 3. 每单元施工输入

每次明确：所改目录、所属产品设计、架构接口章节、依赖状态、验收用例与不在范围的功能。协议/持久化提案先验证关键假设，再登记正式接口，不一次性冻结一套未经运行的巨型 API。

测试、提交及文档更新纪律继承 [根章程](../AGENTS.md)，命令见 [开发操作](development.md)。完成一个可独立验收的单元即提交推送，不把整个联机系统攒成一次大提交。

## 4. 进入联机实现前的检查

- 确认使用最新摆球交互，保留用户当前物理参数与已验收镜头手感。
- 识别现有 UI 的房间、长局制、暂停占位，不能当作后端能力已具备。
- 核查 AI/物理共享状态；完成真实触球与网络截止原型。
- 对影响当前单元的待决项先确认，其他事项留在项目状态，不反复散落提案数值。
- 本轮文档整理不代表已完成以上实现或已复测摆球浏览器专项。
