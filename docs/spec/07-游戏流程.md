## 1. 模式定义（observed，L3662-3701 + L3166-3173）

侧栏菜单仅两项：`single play` / `practice`（L3166-3167）。差异只在于**玩家列表**：

| 模式 | 玩家列表 | 初始化 | 说明 |
|---|---|---|---|
| practice | `[USER]` | `reqEditorReset`：`inHand=1, ballOn=65535(任意球合法)` | 自由练习，无对手 |
| single play | `[USER, AI]` | `reqReset`：`resetGContext`（inHand=2, ballOn=RED） | 轮流对战 |

- AI 不是独立引擎，就是 `players[1]`（`PLAYER_TYPE_AI`），通过与玩家相同的控制器通道击球（06 文档 §6 已证）
- 难度选择框 "SELECT LEVEL"（L3465-3492）：AI-1(等级2.5)→EASY、AI-2(4)→NORMAL、AI-3(5)→HARD，即simple/medium/hard
- **两模式共用**：规则实例（`std-sno`→模54）、球台场景（模96）、gState 状态机

## 2. gState 状态机（模15 枚举 L8922-8931）

位掩码：`ERROR=0, NO_GAME=1, PENDING=2, READY=4, SIMULATING=8, JUDGING=16`

```
NO_GAME → PENDING（asyncLaunch 装配场景/玩家/规则实例）
PENDING → JUDGING（reqReset/_onResetResponse 首次布局）
JUDGING → READY（_response 结算+快进+快照后）
READY → SIMULATING（reportPlayerStroke：仅 playerIndex 当前玩家可击球）
SIMULATING → JUDGING（reqRoundResult：球停后结算）
JUDGING → READY（下一杆 / 换人）
```

## 3. 击球权与计分（`reqRoundResult` L3732-3752，observed 全读结）

```
checkResult(ctx, sim, refResult) 得 {score, foulCode}（规格 05 §3）
nRounds++
score > 0（连续得分）：
    player.pts += score;  scoreCount++;  brk += score   // 连击(break)累计
    playerIndex 不变     → 继续击球
score ≤ 0（失机/犯规）：
    player.penalty += score;  brk = 0
    playerIndex = (i + 1) % nPlayers                    → 换人
```

玩家计分字段（`xe.a` Player 类，L3663）：`pts, scoreCount, brk, penalty, shootingCount`——single play 记分板数据源；`clearScores` 在每次 reset 调用。

## 4. 结算快进与快照（`_response` L3754-3765，observed）

```
while (sim.nAwakened !== 0): sim.step(0.1)   // ≤200 次保护，超出抛错
sim.save()                                    // 世界快照（serialize，规格01 §4.4）
gState → READY
```

意义：每次进 READY 前世界必然静止且已存档——**换人/重置彩球的物理后果在瞬间结算完**，玩家看到的"球停了"即快照点；也是悔 шар/回放的数据基座。

## 5. 手中球（inHand）流程（observed）

- `inHand`：2=待放置 → 1=已放置 → 0=正常
- `reqRespotCueball(L3726-3735)`：READY 态下校验射线落点在有效区（D 区圆盘，规格 05 §5）且不贴球 → `respotIndexXYZ` → inHand 降为 1
- `isValidInHandPositionUnderRay(L3777-3781)`：鼠标射线拾取摆球的实时校验（UI 渲染合法区提示）
