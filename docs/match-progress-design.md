# 整场身份与换局

2026-11-08 授权实施。对应联机计划 B 的首个单元；仅扩展经典开发联机。产品换局行为以 [双人流程](multiplayer-design.md) 为准，重摆政策以 [生命周期](match-lifecycle-design.md) 为准。

## 本轮边界

核心 `MatchProgress` 负责整场、单局、尝试的身份、开球序列、局分、局间准备和唯一结果。`GameSession` 继续裁决一局，服务器组合两者，不改本地人机、练习或物理。账号、完整存档、暂停、重连和数据库不在本轮；“保存”当前指服务器内存里的稳定比赛事实，不意味着重启后恢复。

每场使用服务器生成的唯一 matchId；房间码不是比赛身份。frameId 随下一局改变，attemptId 只随本局重摆或下一局改变。一杆的 shotId 属于本局尝试：准备时预留，真实触球才计入实际杆数，取消的准备不算一杆。Miss 复位不新建本局尝试。

核心登记重摆尝试的能力并测试其不换局、不换开球方、不改已完成局分；本轮不开放协商重摆命令，也不把本地 reset 接成联机重摆。

## 换局与结果

只消费 GameSession 的最终胜者；末黑平分仍由原裁判继续争黑。稳定状态允许本人确认认输本局，运动或待触球期间拒绝，不能中断一杆。两种结束路径都只记录一次单局结果；累计达到赛制胜局要求时产生一个稳定整场结果 ID。

非终场进入 between-frames，双方分别准备后才新建下一局 GameSession；上一局比分保留到此时。只完成一方准备不会重置球台。重复命令、重复准备和过期版本不得重复加局分或跳局。断开连接清掉该席位的局间准备。

服务器默认三局两胜，支持启动参数选择已确认的局数。首局随机抽取一次；测试可固定，后续每局交替。新局使用标准开局、清单局分和杆数，保留整场局分。版本与事件序号跨局单调增加，旧局动作不能污染新局。

## 客户端验收

继续用开发网址入房；增加独立的小型整场面板，显示第几局、局分、开球方、本局认输确认、局间准备和整场胜者。调试 HUD 保留；正式比分牌、力度条、声音、犯规提示以及创建/输入房间码属于后续独立接线单元。

换局时清理旧球位缓冲与对手球杆显示，不把新一台球与上一局末态做运动插值。既有同局运动时基、瞄准姿态和摄像机所有权不改。

验收覆盖真实末黑入袋、平分争黑不提前结算、2:0/2:1、双方准备、轮换开球、重复及迟到命令、非法席位、终场拒绝出杆、两房间隔离；浏览器双窗口验证局间操作和新局真实击球。计数幂等目前限同一服务进程，跨重启事务保证留到持久化单元。

## 人工验收步骤

协议升级为 v4：先在原终端 Ctrl+C 停掉旧服务器，再运行：

```bash
npm run net:server -- --host 127.0.0.1 --port 8787 --dev-token dev-local --best-of 3
```

Vite 保持 `npm run dev`。刷新原先两个地址，分别占席位0和1：

```text
http://127.0.0.1:5173/?net=dev1&token=dev-local&seat=0&interp=100
http://127.0.0.1:5173/?net=dev1&token=dev-local&seat=1&interp=100
```

1. 两端右下角应显示相同的赛制、局分、本局比分和开球方；界面玩家1/2对应席位0/1。
2. 按正常方式打一杆；运动及待触球期间不能认输本局。稳定后点“认输本局”，再确认，可快速触发局结果；正常清台也进入相同换局流程。
3. 玩家2认输后局分为1:0。一端点“准备下一局”只显示等待，另一端也准备后才开始第二局。本局分回到0:0、整场局分仍是1:0，开球方与第一局相反。
4. 第二局玩家1认输，局分变1:1；双方准备第三局，开球方应与第一局相同。第三局玩家2认输，显示玩家1以2:1赢得整场，不能继续出杆或准备第四局。也可连续让同一玩家认输两局验证2:0提前结束。
5. 对手旁观、W入位球杆、Space实际触球及手动镜头应保持此前体验。旧局迟到动作与重复结果由自动测试验证，人工不需要修改控制台数据。

需要固定首局先手重现问题时，可在服务端命令追加 `--first-opening-player 0` 或 `1`；正常验收省略，让服务器随机决定。双方都关掉窗口会销毁当前开发房间；结束后换一个 `net` 值可建立另一场开发比赛，这不是正式“再来一场”产品入口。
