# 母球摆放：交互修复设计

状态：2026-11-06 用户确认，待实现。本文先于联机开发执行，只修复摆球交互。

## 1. 已确认的行为

摆球资格与摆球工具是否打开是两件事。放好母球、进入瞄准、再起身，都不消耗手中球资格；真正击球后才按规则结束该资格。出杆动画准备阶段暂时禁止改位，若实际触球前取消，应按规则状态恢复操作；超时换人不能把资格还给旧玩家。

放置成功后光环消失，普通鼠标移动不再显示候选点。还想调整时按 P 重新拿球。这取代之前讨论的“放好后一直保留绿色光环”。

| 状态或输入 | 反馈和结果 |
|---|---|
| 进入摆球工具 | 母球当前原位显示白色旋转光环 |
| 鼠标指向合法落点 | 候选点显示绿色 |
| 鼠标指向可投影但不合法的落点 | 候选点显示橙红色，不能提交 |
| 鼠标射线无法与台面平面有效相交 | 隐藏候选点，标记不可提交，不能沿用旧绿点 |
| 单击合法位置 | 放置母球、收起光环、退出工具，保留手中球资格 |
| 单击非法位置 | 不移动母球，不自动改放到边界或上次合法位置 |
| 按住鼠标拖动 | 只改变观察方向；在台内或台外开始拖动都不落球 |
| 普通状态按 P | 有资格且非出杆中时，重新打开摆球工具 |
| 摆球中按 P/ESC | 取消本次工具操作，保留上次已放好的位置和手中球资格 |
| 按 W | 当前实际母球位置合法时收起工具并瞄准，不把鼠标悬停点当成新落点 |
| 瞄准后未击球就起身 | 仍可按 P 重新摆球 |
| Enter | 保留为合法候选点的确认快捷键，成功后与点击放球相同；没有候选时仅允许确认实际合法母球位置 |

经典开局及手中球受 D 区限制。900 开局及蓝球决胜按现有规则使用 D 区，普通犯规后全台手中球使用合法台面范围。不得把 900 的全台权限推广到所有情形。

用户已确认改成原作的落点校验：只检查最终位置的区域与球体间距，不检查从原位到落点的移动路径。母球是拿起后放下，不要求沿台面绕过其他球；最终与其他球重叠、越出许可区域或落入不允许摆放的位置，仍然拒绝。

保留母球摔袋后重新回到台面时的自动聚焦。自动聚焦完成后由用户自由观察；拖动、悬停和取消不能不断把镜头拉回母球。更新球杆瞄准锚点与强制调整当前观察方向必须分开。

## 4. 输入与状态处理

鼠标按下只记录位置、指针身份和起始状态；松开时才判断是否提交。移动超过小幅阈值视为拖动。阈值采用 CSS 像素，实施时固定并加入测试，不随设备像素比改变手感。

拖动期间冻结摆球预览，镜头照常移动；结束后重新计算候选点，但这次松开不触发放置。点击提交必须基于本次坐标和当前相机重新拾取，不允许使用上一帧或上一处绿点。

按下后发生失焦、pointercancel、工具退出、球权变化、出杆锁定或菜单接管时，丢弃待提交点击。只有主按钮的完整点击才可落球。

UI 层的候选校验用于反馈；最终放置仍由对局权限和 Simulator/规则命令校验。服务端联机后同样验证座位、球权、区域与落点，不信任客户端“绿色”的声明。

禁止以隐藏光环清除核心手中球资格。禁止在 `prepared` 或真正出杆中改位；未触球取消与已触球结束必须分清。AI 的合法落点选择仍走核心，不需要模拟鼠标。

## 5. 计时、暂停和镜头边界

900 打开摆球工具、放球、P/ESC、W 均不停表、不补时。实际触球才停止本杆出杆表。经过用户批准的正式暂停是独立例外，见 [比赛生命周期](match-lifecycle-design.md)。

如果在鼠标按下与松开之间超时，旧玩家的点击必须失效。W 确认时也先检查截止和位置，不能通过切模式获得额外时间。

非法实际球位必须先有明确合法放置才能出杆；可以提供预览起点，但不能在 W/台外点击时静默选择一个新位置代替用户。

本次不调整已经验收的站立、瞄准、起身、跟随及 AI 旁观算法。自动聚焦只服务于需要重新摆母球的入口。

## 6. 验收

1. 经典：D 内候选绿色、D 外橙红；D 外点击或拖动不改变母球。
2. 900：全台手中球的候选点超出合法台面时不可提交，不截回库边落球。
3. 两模式：台内/台外按下后拖动，仅镜头改变；拖动结束不放球。
4. 成功放球后所有摆球光环隐藏；普通鼠标移动不出现候选光环。
5. 再按 P 可再次摆放；W 瞄准、起身、P 重摆连续多次仍有效，实际触球后资格消耗。
6. 从一个合法点跨过其他球选另一个合法点允许；落点与球重叠则拒绝。
7. 失焦、菜单接管、pointercancel、球权变化和超时后的松开都不能提交旧点击。
8. 摔袋后的自动聚焦保留；此后手动观察不被再次抢走，实际瞄准时球杆锚点正确。
9. 900 反复操作不补时；AI 摆球及默认合法开局 W→Space 不回归。
10. 自动化覆盖输入与状态，Chrome 专项覆盖真实点击/拖动/光环，再由用户试打。

实现时先更新 `architecture.md` 中受影响的窄回调契约，维持旧调用方兼容；不得用本设计自行改动物理求解器。每个实现单元全量测试和类型检查通过后提交推送。
