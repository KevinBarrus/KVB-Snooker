# 声音第一版

2026-11-07 整理。本文维护真实声音链路、事件与选样行为；资产准备流程区分早期原声集与后续处理集。声音为项目扩展，PCOL 仅提供碰撞和出杆时序依据。

## 范围

杆头击球按实际高低击点/力度选组；所有球球碰撞按法向相对接近速度选组；入袋按实际入袋球进入袋喉阶段的水平速度选择空心/磕袋角素材。低速入袋连续趋近静音。暂不做长短台、抬杆库边、起跳、普通碰库和犯规声音，运行时不自动对原素材降噪、剪辑或补尾音；离线处理实验与已安装资产另行区分。

local-audio 保持原素材，生成资源在 public/assets/audio，两处媒体均不提交。运行时只消费安装后的清单；原声准备与后续处理集安装是两条产物路径，不能把两者混称为全部原字节复制。

## 数据与分层

- Simulator.onImpact(listener):()=>void 提供只读 ImpactEvent；Node 可消费，回调可解除。不暴露 Body、Contact 或可变 Vec3。
- ImpactEvent 为 cue / ball / surface 联合；共用 time（世界演化步对应秒数）、ballIndex、x/z。cue 包含 speed（StrokeVars[6]）、tipHeight（沿实际击球方向垂直平面的归一化击点高度）；ball 包含 speed（非负法向相对接近速度）；surface 包含 surface（jaw/pocket/tunnel/end）、speed、horizontalSpeed 及离台前速度 entrySpeed；正式载荷签名由架构 §9 维护。
- Simulator 在 stroke 的实际冲量时刻发 cue，在现有 onTouch 求解前发 ball/surface。仅观察，不改变求解/积分/规则；预测静默。不使用原 out-of-bounds 事件替代进袋。
- BrowserGame 将 onImpact 桥接到 EventBus 的 sim/impact。旧事件不改。audio 仅消费类型化事件；根 app-audio 装配浏览器播放器与现有 EventBus。
- audio 中纯选样/音量决策与浏览器后端分文件；浏览器后端独立 DOM 编译环境，其他 audio 和全部 core 保持 Node 可运行。不引入音频库。

## 入袋判定与时序

PCOL L12351-12365：tunnel 为 PREPOT，end 为 POTTED；pocket 是袋喉内壁，sidesoft 是袋角周围软库。音效在首次 tunnel 接触播放，end 仅兜底；每球每杆一次。优先读取近期 pocket 的 entrySpeed，无 pocket 时使用 tunnel 的 entrySpeed；它记录离台前水平速度，避免袋内下落和漏斗响应放大轻推进袋。即时 horizontalSpeed 保留为观察证据。

jaw 接触必须与袋喉在可配置的时间/距离范围内，才使用磕袋角素材；普通远处库碰撞不触发。候选 pocket 状态超时/远离后不复用。首版此分类是依据网格的可测近似，不是原作声音算法。复合磕袋角素材只播放一次，不叠加空心样本。正式计分仍仅由既有裁判处理。

## 播放策略与校准

同组使用洗牌袋，每轮用完再打乱，跨轮避免立即重复；随机源由装配根注入且不消耗 coreRandom。相邻力度档用连续权重选择音色，音量按连续曲线计算；高低杆由实际击点分类，缺档使用该杆法已有相邻档。全部阈值、权重、力度曲线、样本增益在音效配置/清单集中维护。

早期原声准备工具测量每段 WAV 最响 20ms 窗口 RMS，生成有限播放补偿；后续处理集可把电平与尾音烘焙进生成文件。两者不能叠加重复补偿，不把测量峰值当真实击球力度。原分类仍为依据。同组响度校准与事件动态增益分离，主音量及总线压缩保留叠加余量。听感须由用户最终验收，自动验证仅证明数值/时序和真实发声。

原生 Web Audio 预加载并解码，用户手势解锁，加载/解码失败提示但不阻止游戏。音量控制持久化，切新局/复位/回放停止遗留声音，销毁释放监听和节点。首版回放静音，不修改原回放录制格式或摄像机。

## 验收

- 核心事件：真实接触、预测静默、事件有无不影响存档/结果、退订、偏心击点、入袋速度与网格标志。
- 纯音效：连续响度/分档边界、组内不重复、未知/非有限参数静音、轻入袋静音、袋角近邻/过期、单球不重复、独立随机源。
- Chrome：所有素材真实解码；击球瞬间而非后拉触发、真实球球/入袋声、Web Audio 输出非零、音量/静音、预测不发声、切局/回放无旧声、资源失败不阻塞游戏。
- npm run test、npm run typecheck、npm run build 与相关浏览器回归；按根章程更新所属设计及必要章程，再提交推送。

## 运行与调整

- `npm run audio:prepare`：根据 scripts/audio-sources.json 校验原素材并生成早期音效集，包含播放偏移及增益策略。
- `npm run audio:install`：安装 scripts/audio-final-set.mjs 管理的后续处理集；其电平/混响已按该流程处理，不自动再加一层运行时混响。
- 两者写相同安装目录，不能连续执行后假定获得混合集。以最终安装清单确定实际播放资产，条数不写成永远有效的章程。
- src/audio/calibration.ts 管理动态曲线和组间增益，素材选择与离线处理由对应脚本/清单管理。参数值以文件为准，不在多个文档复制当前数字。
- 缺素材不阻止对局；原始录音保持不变。准备、运行和浏览器命令见 [开发操作](development.md)。

surface.entrySpeed 的校准依据：历史轻推实例离台前 0.115 m/s，首次 tunnel 已为 0.376 m/s，因此在台面采样并在球球求解后刷新，低于台面保留离台前值。观察不改变求解或规则；恢复/新杆清理缓存。
