# 双人联机：房间与玩家流程

状态：已确认产品范围，正式联机尚未实现。本文只定义玩家流程和房间行为；网络机制见 [协议设计](multiplayer-protocol-design.md)，存档机制见 [持久化](match-persistence-design.md)。

## 1. 范围与术语

第一版为登录玩家通过房间码或邀请链接与朋友对战，支持经典和 900，不做公共匹配或天梯积分。游客权限统一在 [账号设计](accounts-and-guests-design.md) 维护，双人规则测试继续是独立开发工具。

- 房间：邀请、席位、比赛设置和准备状态。
- 整场比赛：约定局数下的完整胜负对象，可以跨多次登录恢复。
- 单局：一台球的规则与比分进程。
- 本局尝试：同一局因双方同意重摆产生的新尝试，不等于下一局。
- 一杆：实际触球到本杆完整裁决；出杆前准备不等于已经触球。

## 2. 创建、加入和准备

创建者选择规则与局数后请求服务端创建房间，成功后显示邀请码和复制入口。界面“创建者”没有改分、强制重摆或踢掉对手后获胜的裁判权。

局数沿用现有菜单选项 1、3、5、7、9、11、17、19、25、33、35；先赢得 (N+1)/2 局者赢下整场。显示框只是选择，真实配置必须由服务端保存。

对手通过码或链接加入，经账号权限、房间状态和席位容量检查后才入座；不存在、已满、已结束或无权访问时明确提示。不能接受任意非空文本后直接启动本地双 USER。

入座双方看到相同玩法、局数与对方资料。改变赛制配置使双方准备状态失效；双方确认准备、资源和台面就绪且允许操作后才开始。初始资源加载不扣比赛时间，开始后不得再借“未准备好”免费暂停。

## 3. 开球与进行中

首局开球由服务器随机决定并保存为比赛事实，一局定胜负和长局制一致（2026-11-08 用户确认）。刷新或重连不重新选先，之后按局轮换；争黑和 900 决胜按各自规则文档执行。开发验收可以显式固定首局开球方，不作为正式比赛选先策略。

只有当前持权玩家可提交出杆、摆球和适用的规则选择；另一方可以自由观察。V 三模式只作用于本人出杆，摄像机、音量和菜单不互相控制。

从摆球到瞄准、真实触球、球运动和规则选择复用现有正式核心。不得为了联机创建第二套自由球、Miss 或 900 判罚。具体规则引用 [经典](rules-v2-design.md)、[900](snooker-900-design.md) 与 [摆球交互](cue-ball-placement-design.md)。

## 4. 换局与整场结束

本局结束后展示本局结果并更新整场局分。未达到胜局要求时进入下一局准备，准备完成后开始该局；终局画面不应悄悄消耗下一局出杆时间。

达到整场胜局要求或出现整场认输/掉线判负时只结算一次。个人资料与榜单如何记账由 [统计设计](stats-design.md) 定义，房间不直接增减榜单数字。

整场结束后的“再来一场”建立新比赛，不修改已完成结果。是否继续、如何选先应明确展示，不复用上一场的待处理命令。

## 5. 菜单、退出与异常

菜单展开不改变真实比赛。暂停、暂存、重摆、退出、掉线和服务端故障统一执行 [生命周期](match-lifecycle-design.md)，本文件不另定义次数、期限和判罚。

双方同意恢复的暂存比赛沿用原身份和配置，不通过创建一个相同名字的房间来冒充恢复。未完成比赛与已关闭的临时连接分开管理。

现有菜单的本地占位行为见 [菜单设计](menu-design.md)。正式联机接线时替换占位命令，测试入口保留在开发工具中，不让游客误入。

## 6. 交付验收

- 两个独立账号与浏览器完成创建、加入、准备、经典一局，配置和球权一致。
- 非当前玩家自由观察但不能击球；本人回合恢复既有观察偏好。
- 长局制正确累计局分、轮换开球并只生成一次整场结果。
- 900 双方同权，计时不受另一方菜单、帧率或客户端自报时间控制。
- 非法房间、重复加入、断线恢复和过期按钮有明确结果，不降级成另一场本地比赛。

语音独立见 [语音设计](voice-design.md)，排行榜和高光不是基础击球链路的同步依赖。
