# 比赛持久化与故障恢复

状态：工程提案，未实现。本文只定义保存、事务和恢复机制；暂停、暂存期限、重摆及判负政策以 [生命周期](match-lifecycle-design.md) 为唯一来源。公开存档接口需实施前在 architecture.md 登记。

## 1. 数据分工

建议使用 PostgreSQL 保存关系与事务数据，对象存储保存较大的回放资产。部署厂商不是本文的产品约束。数据库内部恢复日志不等于业务命令记录，不能用 WAL 代替出杆去重或媒体任务重试。

| 数据 | 负责内容 |
|---|---|
| 用户与登录身份 | 稳定用户 ID、验证与公开资料；不以昵称作外键 |
| 房间与比赛 | 参与者、席位、规则版本、整场配置及生命周期 |
| 局与尝试 | 本局开球方、局分、重摆前后独立尝试身份 |
| 命令及结果 | 唯一命令 ID、规范化参数、权威接受/拒绝、结果版本 |
| 对局事件 | 杆、裁决、计时与得分事实，支持审计和重建统计 |
| 检查点 | 完整恢复状态、所属事件位置及格式版本 |
| 统计贡献 | 每个结果/里程碑的唯一贡献，可撤销和重建 |
| 高光元数据 | 所有者、可见性、片段引用及回收站信息 |
| 待处理任务 | 通知、汇总、媒体处理和清理；可重试且有幂等键 |

这不是最终表结构。拆表、索引和字段类型应根据查询与事务边界决定，不按文档每行机械创建一张表。

## 2. 完整检查点

当前物理 `SerialData` 只解决物理恢复的一部分，不是整场存档。检查点至少覆盖：

- 整场双方身份、已完成局分、当前局和尝试、开球顺序与生命周期状态。
- 球的物理状态及姿态、球权、双方分数和统计、目标阶段及手中球权限。
- 待处理判罚、提名/自由球、贴球依据，以及 Miss 所需上一杆恢复状态。
- 900 双表、阶段、压哨处理、全台手中球和蓝球双方尝试结果。
- 暂停预算、断线处理信息、已接受但未完成的动作与最近事件位置。
- 引擎/规则/物理配置版本、随机状态及已经采纳的 AI 出杆。
- 单杆统计计时区间、里程碑身份及逐杆回放归档位置。

不保存 DOM、相机、指针对象或运行中的 AI 任务引用。恢复时重新建立这些派生对象，并检查瞄准锚点。AI 已经接受的出杆必须保留，不能恢复后重新搜索一杆不同的球。

## 3. 写入与确认

每个房间由有效写入者顺序执行命令。通过唯一约束及版本检查保存命令结果、状态变化和对应事件；只有必要持久化成功才发成功确认。

如果数据库提交失败，不能让内存世界继续对外声称该动作成功。实现可采用暂存状态后提交，或失败后从已提交边界恢复；选择哪一种需在事务原型中验证。不能以重试数据库写入为由再次调用真实 stroke。

每杆结束建立稳定检查点。中途暂存等待的安全边界由生命周期定义；不要为了方便存档而改变“已触球的一杆必须完整结算”的规则。

运动中发生进程故障，优先从上一检查点和已接受命令恢复。必须验证同版本重放、随机消耗、时间和规则事件结果；不假定只存种子就可复原。若无法可靠恢复，进入明确的技术中断处理，禁止默默允许重新选杆。

## 4. 统计与任务幂等

整场结果、单局结果和单杆里程碑各有唯一身份。统计贡献与对应权威结果建立事务关联；结果通知和媒体任务通过事务内记录的待发送任务触发。

工作进程可以重复收到任务，消费者依据业务身份只应用一次。计数不能靠“只会调用一次”的假设；失败重试、服务器重启和用户重新登录均不能重复加胜场。

重摆使旧尝试的贡献失效，保留审计事实并重新汇总；不是删除录像就撤销成绩，也不是保留录像就继续上榜。统计业务口径只在 [统计设计](stats-design.md) 维护。

## 5. 时间与版本

进程内单调时钟适合计算区间，但不能直接序列化后在另一进程继续相减。记录可恢复的剩余量、权威时间基准、累计区间和明确的暂停/中断状态；正常客户端掉线和服务器故障分别处理。

保存格式、规则、物理配置和回放格式分别版本化。长期暂存需要保留兼容运行版本，或经过对照测试的迁移。不能静默加载最新版改变存档手感，亦不能用数据迁移伪造已确认结果。

## 6. 高光资产

数据库保存条目和引用，对象存储保存不可变片段；上传采用临时对象与完成校验，成功后才发布可播放状态。对象存储与数据库不是一个原子事务，使用可重试状态转换和孤立对象清理处理失败。

权限由服务端校验，不靠不可猜 URL 代替。拼接通过有序引用生成新条目；删除条目按引用关系清理独占资产。隐私默认值、回收站期限及恢复行为只在 [高光设计](highlights-design.md) 定义。

## 7. 故障验收

在接收命令、提交结果、发送确认、运动中、结算、写统计和上传资产各位置注入故障。验证：接受过的动作不丢失或重做，拒绝不改状态；终局只提交一次；恢复不改球权、罚分、时间、提名或出杆意图。

另测同一比赛两个写入者竞争、旧版本检查点、重复任务、数据库不可用、对象上传一半失败。上线前必须实际恢复备份；“有备份文件”不等于能恢复比赛。
