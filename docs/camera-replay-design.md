# 击球观察模式与本地上一杆回放

2026-11-07 合并现行要求；历史提交与测量见文末存档。本地回放不等于正式联机或高光播放：900 活跃局禁用暂停式回放，联机不得暂停对手，长期收藏见 [高光设计](highlights-design.md)。

## 1. 目标与已确认边界

大力薄球碰撞后，原有注视点持续追随高速母球，容易产生急促转头感。本次增加观察模式，改善实时观察，并接入上一杆回放。

默认“自然起身”以用户认可的原版观感为目标：自然抬高、后退，不明显追逐任何运动球。原作源码仍包含缓慢 follow，不能把本次稳定注视策略标为原作逐行转写。原作事实继续保留在 spec04；本文件记录用户批准的体验扩展。

三种模式共享现有身体/头部起身位置轨迹、跟杆后0.5秒等待、1.2秒基础过渡和距离修正。模式只改变视线焦点，不改变击球、物理、规则、站位和起身高度。跟随模式也必须自然抬高、后退。

## 2. 观察模式

| 内部值 | 提示文字 | 行为 |
|---|---|---|
| natural | 自然起身 | 默认。出杆时确定稳定观察区域，随起身平滑看向台面、站直时同步到位，不使用运动球实时中点，不随碰撞变向 |
| cue | 视线跟随母球 | 持续观察母球，允许偏离中心，接近画面外围时加强跟随，抑制突然甩头 |
| object | 视线跟随子球 | 首碰前轻随母球，首碰后连续交接给该子球；之后不因连锁碰撞换目标 |

目标失活、落袋或出界时保持最后的台面观察点，不向袋底追踪，不突然切换其他球。稳定观察区域、跟随响应参数通过大力薄球绕台、K球、直球与长台验收；不能用静态截图代替动态检查。

跟随采用随时间推进的平滑响应，限制转向突变，同时以画面内偏移衡量是否需要加强响应。目标不是逐帧钉在正中央，也不能因固定的低速上限长期掉到画面边缘。三模式切换从当前实际视线接续。

## 3. 操作与偏好

- V 顺序循环：自然起身 → 视线跟随母球 → 视线跟随子球。核查现有输入表后使用86键码；不覆盖已有功能。
- 每次切换短暂显示准确的中文模式名。保存偏好，刷新与新局后沿用；缺失、非法或不可访问的存储回退自然起身，不影响游戏运行。
- 自己击球的球运动期间允许切换，平滑过渡。子球尚未确定时不猜测目标。AI回合自由旁观，V无效且不改变偏好，详见下文“AI 与远端旁观”。
- 玩家主动拖动观察立即手动接管；松开后本杆不自动抢回。联机出杆收尾、规则结算及再次获得球权也不得恢复拖动前的自动焦点；玩家主动按 W 进入下一杆瞄准时才重新对准母球。自己回合再次按V重新启用所选自动观察；自己下一杆恢复保存的模式。AI出杆不会解除用户手动观察。
- 手动接管不覆盖保存的偏好。加塞拖拽与手中球放置不误当作观察接管。
- 回放期间复用V观察切换与手动接管，不让操作穿透到真实对局。

## 4. 上一杆回放

- 摄像机图标进入上一杆回放；无完整记录时不可用。
- Space成功发起出杆时立即隐藏并禁用入口，从后拉阶段即生效；不能等到物理触球。
- 本杆动作与模拟结束并完成记录后重新开放入口。新局清除旧记录。
- 第一版提供播放/暂停、正常/慢速、重播与退出；回放内Space播放/暂停、Esc退出，V切换观察对象。原作C相机切换语义先核对，避免擅自复用为现有清塞。
- 默认使用原作固定全台斜俯视机位；按V后在同一机位切换观察焦点，拖动仍可手动观察。重播或拖动进度恢复全台视角，避免沿用上一播放位置的目标锁定。
- 录制已经发生的球显示姿态及相机/球杆动作，不重新计算另一条物理轨迹。记录只保留上一杆；限制记录规模，超限不发布不完整回放。
- 现有本地回放播放期间暂停真实对局与AI调度，不调用真实Simulator的stroke/step/restore，不改变分数、回合权、随机序列和待击球状态；退出恢复原来的画面与输入。
- 复用已有逆向记录，并在实现前读取 analysis/1.chunk.js 的回放按钮、录制、MovieClip与播放控制源码，补齐行号与怪癖。原作文件和取证中间产物不提交。

## 5. 分层与契约

- controller：击球观察策略、平滑焦点、手动接管、录制与播放状态。通过Simulator的现有只读视图与getResult读取球数据；不读取World/Body，不导入ui/render。
- ui：模式短提示、回放按钮与播放控件。沿用状态类与DOM视图分离；接受装配根传入的状态与回调，不导入controller。
- render：继续消费getBallCount/getBallView结构视图，由装配根选择实时或回放快照，不感知回放控制器。
- app.ts及拆分装配文件：偏好存储、输入路由、录制时机、显示源选择、真实对局暂停和恢复。浏览器存储只在装配根访问。
- 不增删architecture §3事件或§4.2核心接口。新增表现层接口及装配回调在architecture中登记；回放数据采用独立快照，禁止借用核心可变引用。
- 工程和文档纪律继承根章程；新增策略如非原作算法，不伪造 PCOL 出处。

## 6. 验收

每个代码单元跑npm run test与npm run typecheck；涉及浏览器装配另跑build和对应Chrome验收。最终覆盖：

- 相同出杆下三模式的位置轨迹逐帧一致，母球高速横向移动不改变自然模式焦点。
- 跟随模式转向连续、跨帧率响应稳定；快速目标在起身后尽量位于中央宽区域。
- 运动中连续切换、未撞球、首次目标落袋、手动拖动后松开、下一杆恢复。
- V不影响瞄准/力度/加塞/出杆；偏好刷新恢复与存储失败回退。
- 出杆入口立即隐藏回放；无记录/新局/运动中均不可进入。
- 播放、暂停、慢放、重播和退出；真实对局存档、分数和回合权前后一致，退出后可继续击球。

自动化通过不等于手感最终认可；交付时明确大力薄球绕台的实机主观验收仍由玩家确认。

## 7. 回放源码证据与实现差异

复用REA保留证据 `ev_5e5e1ba396c71c303fe9f62f48ee774385d944038817c8a62b8e16906eb38a3b`；静态图覆盖为partial，以下结论以原包逐行阅读为准，未运行完整原作程序。

| 行号 | 已核对行为 |
|---|---|
| L4134、L6275、L7776-7790 | 摄像机入口；片段时长>0.5秒才提供回放；SHOTTING_START立即移除入口 |
| L6311-6346 | 出杆时清空旧记录，记录相机/球杆/球；球步进间隔>0.1秒停止录制 |
| L6810-7060 | 时间轴与采样；球位置/显隐/阴影插值；停球延长关键帧寿命 |
| L7104-7140、L7180-7206 | Space播放暂停，S按住¼速，C切换镜头，Esc返回；进入播放0秒，退出重新同步真实球 |
| L7225-7263 | 尾端播放重启、进度定位、独立镜头控制器与录制镜头切换 |
| L7270-7354 | 相机位置/注视点、球杆显隐/位置/最短转角插值 |
| L7375-7525 | MovieClip管理轨道，限定容量，正向播放到尾停止 |

本次实现采用统一约60Hz显示快照，额外记录球的显示四元数并归一化插值。最多7202帧/120秒，只保留上一杆；出现>0.1秒记录间隔或容量不足时丢弃整段，不提供残缺片段。原作是分轨采样和静止段压缩，本次未复制压缩布局或二进制格式。

当前默认原作全台机位，V 复用观察模式。第一版不实现原作C切换的自动袋口特写、路径压缩与变焦，¼慢放使用明确的切换按钮。所有差异均限表现/播放层，不改变已完成物理、规则和核心接口。

`ShotReplay`只持有复制的BallView、相机与球杆姿态；`BrowserReplay`通过装配回调录制，通过独立Input播放。BrowserGame在回放期间提前返回，不推进AI/真实模拟；BallRenderer仅消费装配根提供的getBallView。退出不调用restore，不依赖保存/覆盖真实世界来恢复。

验收包含物理序列化、分数、回合权、真实相机控制器状态前后相等；AI回合回放10秒不推进AI；进度条获焦时Esc也能退出。浏览器脚本：`npm run test:camera`、`npm run test:replay`；截图留在`.cache/`，不提交。

## 8. 当前平滑参数与全台机位

回放机位依据 PCOL L7160–7169、L7186–7188；当前球台 eye=(3.43,2.08,0)，target=(0,.88,.00001)。V 只改焦点，重播/定位恢复全台，用户可手动观察。

自然焦点随同一起身比例到位；跟随平滑器限制 yaw/pitch，角速度随视场偏离为 1.4–3.4 rad/s，角加速度上限 12 rad/s²，不在到达目标时突清转速。

子球首碰前复用母球跟随，首碰后用约 0.3 秒平滑权重交接，不重置转速，之后锁定首碰子球。失活保留最后台面点。回放四分之一慢放只改变轨迹时间，观察响应仍用真实帧时间。

## 9. AI 与远端旁观

三模式只控制本人的出杆观察。AI 思考、瞄准、出杆与连续得分不启动本地用户 ShotView，不归中、不解除手动观察。实时 V 在非本人球权时无效且不改偏好；本人再次出杆才启动保存模式。回放独立处理输入。

装配按 locallyControlled 和实际席位判断，不能以玩家编号推断人类或 AI。正式联机沿用此所有权边界，不同步对手相机。
