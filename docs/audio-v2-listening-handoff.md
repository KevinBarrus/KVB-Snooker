## 1. 任务目标与当前授权边界

用户已验收声音第一版，反馈存在明显的“播放感”，希望声音更自然。用户接受**自然、克制的电视转播感**，现有素材来自比赛转播，暂不要求重新采集或更换整套素材。

本轮先交付 **6～10 段代表素材的可重复对照试听包**，判断剪切边缘、底噪、额外混响、现有增益补偿分别对听感的影响。不要一次叠加所有效果后宣布改善，更不要将自动测试通过当作听感验收通过。

先完成试听包并交给用户选择。用户选定有效处理后，再批量处理候选素材或接入正式游戏；后续接入不属于本轮自动执行范围。当前不训练模型、不增加物理事件字段、不改摄像机、不做观众环境床。

这是新声音设计实验，不是 PCOL 原算法复刻。文档可以解释设计依据；代码注释仍遵守仓库章程，不伪造 PCOL 行号。

## 3. 已确认的基线与需要纠正的推断

上轮检查了79个WAV，总长约26.99秒，格式48kHz/16-bit/双声道；各文件摘要与来源清单一致。

| 项目 | 上轮观测及含义 |
|---|---|
| 末尾能量 | 最后10ms双声道采样合并计算RMS，21段高于−40dBFS，3段高于−20dBFS；仅用于筛选可疑截断，不能据此断言都有可听见的咔声 |
| 峰值 | 60/79段峰值在−0.3dBFS以上，并非全部；缺少原始增益记录，不能“撤销归一化”恢复真实力度 |
| 声道 | 左右相关系数中位约0.99996，最低约0.889；多数接近单声道，但不能说全部完全相同 |
| MP4 | 抽查是AAC音轨；编码格式不足以确定噪声来源、上游码率或转码次数 |
| 观众 | `local-audio/观众`为空；零点几秒的79段片段不能提供20～60秒连续观众录音 |

当前链路：

`Simulator.onImpact → EventBus(sim/impact) → SampleMixer → AudioBufferSource → Gain → Compressor → master → destination`

必须保持准确的代码理解：

- 力度同时参与样本分档选择和连续音量计算，不是只改音量。
- 相邻力度档按连续权重选择一档，不是两档同时播放。
- 同组洗牌、跨轮避免立即重复；声音随机源不消耗物理/AI的coreRandom。
- 正常播放会播到文件末尾；新碰撞不会无条件截断旧声音。24声部上限、静音、切换场景/回放或释放会停止声部。
- 当前没有额外混响、定位或环境床，但录音本身可能已有混响，不能称它为真正的干声。
- 准备工具按最响20ms窗口RMS生成最多±6dB播放补偿；按相对峰值−24dB检测起音并保留3ms前导。它们都是待试听验证的启发式参数，不是已证明正确的听感校准。
- 入袋声音使用入袋球的entrySpeed，不能退回出杆力度或袋底速度；真实轻推测试曾出现离台0.115m/s、首次漏斗接触0.376m/s。

## 5. 处理实验：每次只改变一个因素

每段制作以下版本；不适用的处理可以标注并跳过，不强行加工。

| 版本 | 处理 | 比较目的 |
|---|---|---|
| A | 第一版实际播放基线：沿用其播放起点，无新增处理 | 保留可回退参照 |
| B | A + 仅处理必要的剪切边缘 | B对A：边缘处理是否改善突兀感 |
| C | B + 轻度、针对性的降噪 | C对B：是否降低噪声且不损害撞击 |
| D | B + 少量共享房间混响 | D对B：是否改善连贯性而不变闷、变远 |

完整原始WAV另保留为参考入口，不将它与裁过前导的游戏基线混淆。原始起音、基线起点、处理起点必须有清楚的时间映射，禁止重复应用播放偏移。

### 边缘处理

- 不统一只保留前40～60ms；尤其不能删除袋口录音内部的多次撞击。
- 可将15～30ms淡出作为有明显截断样本的试验起点，长度/曲线由配置控制，按实际尾段调整。
- 不在每段撞击开头机械加长淡入，以免磨掉瞬态。只有确有剪切不连续时才做最小处理。
- 淡出能柔化结束，不能恢复被剪掉的原始尾音。

### 降噪

- 先判断是否存在可以可靠识别的噪声；不要把录音开头的弱撞击或房间反射当纯噪声学习。
- 有稳定底噪时尝试保守处理，并检查被去除的残差信号是否包含撞击或有效尾音。
- 没有合适噪声片段时说明限制，可以不生成C版本；不要自动用语音降噪器处理台球声音。
- 噪声门不是无损修复，同样需要检查弱尾音是否被切掉。
- 优先现有工具，无需新增训练流程或大依赖。记录工具版本和参数，保留原件。

### 混响

- 保留原声主体，用共享send试验少量混响；不得将已有湿声默认全量送入纯混响路径。
- 可以生成固定种子的合成IR，必须标为合成效果，不声称是实测体育馆/克鲁斯堡IR或真实尾音恢复。
- 提供无额外混响基线及少量候选强度；不预先把wet=0.3作为正确答案。
- 记录IR生成方式、采样率、时长、预延迟、衰减、通道、归一化设置及实际增益。不同IR的wet数字不可直接当等响比较。
- 样本播完后保留效果尾巴，输出文件不能在原样本长度处再次截断；保留足够衰减和静默间隔。
- 不增加相机距离衰减、随机声像、随机延时、变调或双样本叠加，避免无法判断是哪项处理起作用。

## 6. 单独核查第一版增益补偿

另做当前逐样本RMS补偿开启/关闭的比较，不把它偷偷混入B/C/D。

- 固定事件力度、样本ID、播放顺序、起音位置和主音量。
- 检查补偿是否把某些片段的底噪一起抬高，或让同一档位的样本差异更明显。
- 需要两种观察：实际游戏增益下的动态表现；同一样本各处理版本的近似等响比较。二者分开标识。
- 等响只用于同一段声音不同处理之间，不把轻碰与重碰统一成同一音量。
- 不能只靠峰值相同宣称等响；短瞬态片段也不能只靠一个LUFS数值。记录匹配窗口、RMS/能量、峰值、输出增益，并允许试听微调。
- 比较时关闭自动音量适配；若经过总线压缩，记录或对比压缩器旁路，防止动态处理掩盖差异。

除孤立声音外，补一个固定短事件序列，用相同选样和时刻模拟“杆头→球球→入袋”，以及少量连续球球碰撞。序列时序必须注明是示例或来自实际事件记录，不冒充新物理结果；各版本保持相同事件，测试单声好听但叠加后浑浊的问题。

工具生成过程应可重复：代码和配置可提交，媒体/大文件不提交；输出目录保持独立，不能覆盖public/assets/audio或local-audio。优先轻量脚本和现有工具，不为一次试听搭建通用音频平台。

## 8. 验收与报告

- 起音对齐，处理参数可追溯；输出长度保留混响尾，不误删有效袋口撞击。
- 同一配置/种子可再生成相同结果；盲听标签映射正确。
- 原游戏代码和正式播放清单保持不变。
- 新增非平凡处理逻辑提供小规模有效测试，覆盖短样本、无合适噪声区等边界。

提交遵守根章程：`npm run test`、`npm run typecheck`全绿；若修改scripts或其他模块，同提交更新其AGENTS记录，但任务正文留在本独立文档。Conventional Commits，完成单元后推送；不提交原媒体、试听WAV或合成IR二进制。

向用户报告：可点击的试听入口/实际打开方式、样本数量、各版本差别、原文件未改、验证结果、已知局限。没有真实听辨能力就明确说明，不能声称自己已听到改善。

建议用户按这些问题反馈：

1. 哪个版本更自然？允许选择“原版最好”或“无明显差别”。
2. 是否出现水声/金属声、瞬态变钝、声音变远或拖尾过长？
3. 是否仍能分清轻碰和重碰、空心入袋和磕袋角？
4. 连续事件是否像同一空间内发生，而不是几个录音片段拼接？

**本轮完成标准是可重复、可公平比较的试听包交付，不是宣布声音已修好。**用户选择后另行定稿游戏接入策略；若效果都不理想，再决定补录、环境床或更复杂DSP。现在不要顺带训练模型、扩展薄厚接触契约或批量覆盖79段素材。

## 9. 技术参考与表述纪律

- [Audacity Noise Reduction](https://manual.audacityteam.org/man/noise_reduction.html)：稳定噪声更适合处理；过度降噪会损害目标声音，可检查残差。
- [Web Audio ConvolverNode](https://webaudio.github.io/web-audio-api/#ConvolverNode)：卷积响应与尾音生命周期；不等于恢复原始录音。
- [Audacity Normalize](https://manual.audacityteam.org/man/normalize.html)：逐段归一化改变原有电平关系；缺少记录时不能还原原始增益。

不要引用未经验证的商业游戏内部实现作为事实；不要承诺“播放感降低一半”“噪声归零”“100%场馆还原”或固定CPU占用。相关统计必须注明测量口径，房间参数与音色处理只作为可试听的设计选择。

## 10. 本轮实施记录（2026-10-28）

工具：`npm run audio:review`（`scripts/audio-review.mjs` + `audio-review-cases.json` + `audio-review-lib.mjs` / `audio-review-fft.mjs` / `audio-review-render.mjs` / `audio-review-page.mjs`）。输出全部写入被忽略的 `.cache/audio-review/`，`local-audio/` 与 `public/assets/audio/` 只读，脚本运行前后自校验两者哈希一致。`--out` 可指向另一个 `.cache` 子目录做可重复性比对。

### 10.1 交付物

- `index.html`：双击即可（file:// 可用），无框架、无 fetch；一次只播一个，停止会立即掐断混响尾；“顺播本组”每版之间停旧版并留 1.5s；版本名默认隐藏，勾选“显示版本名”揭晓（页面内只存 Base64 混淆名，真实映射在 `manifest.json` 的 `blind`）。
- `samples/`：71 个盲标签 WAV（55 个单段版本 + 16 个序列版本）与 `originals/` 8 段原始参照。
- `manifest.json`：素材摘要、测量口径与数值、每版处理参数、IR 参数与种子、C 版残差指标、md5、检查结果。
- `ir/`：合成 IR 参照文件（按峰值 0.9 存储，实际卷积用内存中的能量归一化版本，见 manifest `ir.referenceScale`）。

### 10.3 版本与参数

| 版本 | 处理 | 参数 |
|---|---|---|
| A | 第一版实际播放基线 | 按清单 offset 裁剪，无新增处理 |
| B | A + 末端余弦淡出 | 末尾能量 > −30dB 用 30ms，> −40dB 用 15ms，更干净不处理；三个点名样本给 15/30 两档 |
| C | B + FFT 降噪 | `afftdn nr=12 nf=-40 tn=1`；前置 10ms 静音引导；显式裁齐 25ms 延迟 |
| D | B 干路 + 共享 send 卷积混响 | 合成 IR：48k/2.0s/pre-delay 25ms/RT60 1.4s/高频衰减更快/左右去相关/能量归一化；wet 0.15 与 0.35；尾巴补到原长 +0.65s |
| E | A 的逐样本 RMS 补偿开/关 | 固定主音量 −12dB，两版只差补偿值 |

不做：相机距离衰减、随机声像/延时、变调、双样本叠加、每段机械加淡入。

### 10.4 两个实测发现（影响实现）

1. **本机 ffmpeg 6.1.1 的 `afir` 对本项目 IR 恒输出静音**：用 delta IR、用 ffmpeg 自己生成的 IR、交换输入、`gtype=none`、`precision=double` 均复现，不是 IR 文件格式问题。卷积因此改在 Node 内做（`audio-review-fft.mjs`，基-2 FFT，同输入必得同输出；`tests/unit/audio-review.spec.ts` 用直接卷积校验）。
2. **`afftdn` 恒定延后 25ms（1200 采样 @48k，8 段一致）且不向滤镜图报告延迟**：不补偿会让 C 的整体时间轴后移，起音检查会失败。另外无前导静音时，滤镜起始端会把首 6ms 起音压低最多 1.1dB；前置 10ms 静音后降到 0.1dB 以内。

### 10.5 本轮实测结果（供对照，不代替听感）

- **C（降噪）效果很小**：撞击窗口能量变化 −0.2 ~ 0 dB，尾部（末 100ms）−0.3 ~ −2.3 dB，撞击窗残差 −21.8 ~ −42 dB。也就是说，本轮保守参数下，多数样本的 C 与 B 很可能听不出差别——这本身就是结论之一。
- **D（混响）尾巴**：所有 D 输出长度 = 原裁剪长度 + 0.65s，末 10ms 相对峰值 −46 ~ −84 dB，尾巴正常衰减。
- **D 的干路电平**：6/8 个样本干路与 B 完全同电平（`dryGainDb` = 0）；`cue-heavy`（−4.46dB）与 `pocket-jaw`（−3.0dB）原始峰值已达满量程，混响只能从干路让出，页面对这两组有提示。D-wet0.15 与 D-wet0.35 在同一案例内使用同一条干路，两者只差混响量。
- **E（增益补偿）**：多数样本的补偿值已被 ±6dB 钳位（0.501 / 1.995，即 −6 / +6dB），实际可听差别集中在极响与极轻两个极端。
- **入袋声音**仍使用 `entrySpeed`，本轮没有改动选样链路。

### 10.6 自动验证

`npm run test`（423 项，含新增 22 项纯函数测试）、`npm run typecheck` 全绿。生成器自身检查全部通过：素材摘要未改动、播放起点与第一版吻合、输出 48k/PCM16/双声道、峰值 ≤ −0.5dBFS、盲标签唯一、D 尾巴长度、起音对齐（与同组 A 做首 60ms 互相关，滞后 0 采样）、盲标签映射可逆、未写入 `local-audio` 与 `public/assets/audio`。跳过 2 项（cue-low 与 pocket-jaw 无需边缘处理，故无 B/C）；序列无缺版本。两次生成（`--out .cache/audio-review-verify`）输出逐字节一致。

### 10.7 已知局限

- 素材仍来自比赛转播的短片段，没有可用的干净噪声段；C 只做了保守试探，不代表降噪上限。
- 合成 IR 是设计选择而不是实测场馆响应；D 的尾巴是房间对已有声音的响应，不是被剪掉原始尾音的恢复。
- 淡出只能柔化结尾，不能补回丢失的尾音。
- 序列时序（0/420/850ms、0/60/120/180ms）是示例，不是真实事件记录；序列的压缩版用 ffmpeg `acompressor` 近似游戏总线设置，其 knee 上限为 8dB（游戏中为 12dB），其余参数一致。
- 本轮没有修改 `src/**`、`public/assets/audio/`、`local-audio/`，也没有接入游戏播放链路。
