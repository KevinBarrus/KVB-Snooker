# HUD 与消息显示

本文维护现有 HUD 的显示行为，不裁决游戏规则。视觉原则只在 [UI 章程](../src/ui/AGENTS.md) 保存；菜单见 [菜单设计](menu-design.md)，900 计时器见 [900 设计](snooker-900-design.md)。

## 1. 组件职责

| 组件 | 输入与行为 |
|---|---|
| Hud | 协调类型化事件及只读玩家数据，统一同步视图 |
| ScorePanel | 显示双方得分、单杆和当前目标，不自行更改核心成绩 |
| PowerBar | 显示装配传入的力度和显隐状态，不反向决定实际冲量 |
| ShortcutsBar | 按控制阶段显示可用操作，显示不授予操作权限 |
| FoulNotice / ViewNotice | 显示临时消息，独立计时及手动关闭 |
| RuleChoice / Nomination | 显示核心提供的选择和可用性，回调请求命令，不复制裁判 |
| ReplayControls | 展示装配提供的录制/播放状态，不控制真实核心时间 |

原作显示公式、事件映射依据与历史差异见 [UI 还原依据](modules/ui.md)；公开回调和状态契约仍在架构中维护。

## 2. 临时消息与必要操作

犯规、Miss、贴球、观察模式及临时提名提醒都应自动消失并提供 ×。关闭只影响显示，焦点回画布；不能撤销罚分、自动选择接手或跳过规则选择。

犯规与贴球使用消息组件的自动关闭公式，观察模式使用其独立短提示计时。具体常量在组件维护，不在各章程再抄一遍；原作公式证据见模块依据。贴球同杆去重，后续展示条件由装配根管理。

规则选择面板、提名操作控件和回放控制条不是临时消息，不因通知超时而消失。消息关闭与业务选择要有不同回调。

当前犯规与贴球提示使用英文，不能同时写中英两套标题。完整中英文切换是后续能力；未来统一管理文案，而不是各组件自己猜语言。

## 3. 事件与分层

HUD 通过 EventBus 和装配注入的只读状态更新；当前 ball-on 来自同一份状态，不能各视图各自推导。核心计时快照只用于显示，显示舍入不参与截止判罚。

状态类可在 Node 单测，DOM 视图负责挂载、可访问属性和事件绑定。换局、退订、重复挂载和销毁必须清理监听，避免重复提示或按钮执行两次。

## 4. 验收

- 真实规则事件刷新比分与目标，关闭消息不改变真实局面或选择权。
- 消息可手动关闭、会到时消失，同杆贴球不反复弹出；必要选择仍可操作。
- 键盘焦点和快捷键不会被已关闭弹层吞掉；禁用控件与核心拒绝逻辑一致。
- UI 状态测试无 DOM/Babylon；浏览器验证显示、按钮、焦点和生命周期。
