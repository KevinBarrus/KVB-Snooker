## 1. 权威与进程边界

Node 服务端运行现有无 DOM 核心，负责物理、规则和时间裁决。客户端发送意图并显示结果；不会因为客户端声称“我进了黑球”就结算。服务端基础设施在 core 外，核心不导入 WebSocket、数据库或账号 SDK。

一个房间同一时刻只有一个有效的状态写入者。初版可在单进程内串行处理房间命令；如采用多工作进程，必须有明确房间归属和过期写入隔离，不能让重启前后的进程同时裁判。

当前 AI 路线缓存、随机源及部分物理参数含模块级状态。多房间前验证隔离；不能只创建两个 GameSession 就宣称并发安全。服务器锁定每场规则、物理和引擎版本，本地调参不能改变正式比赛。

## 2. 连接与身份

登录会话决定用户身份，服务器决定房间席位。消息中的玩家编号不能替代鉴权。加入码只用于查找和申请加入房间，不是读取全部存档或占据他人席位的凭证。

连接建立后接收权威快照与版本；同步完成前禁止发出游戏动作。心跳负责发现连接失效，不直接产生比赛结果；重连宽限和责任裁决由生命周期执行。

同账号多标签页应防止多个控制连接同时操作一个席位。建议新连接明确接管控制权，旧连接收到失效通知；重试同一命令仍走去重。接管策略在协议冻结时列明，不能依赖“最后一个包碰巧先到”。

## 3. 命令、确认和事件

以下为信息要求，不是待复制的 TypeScript 公共签名。

| 消息类别 | 必要信息 | 服务端行为 |
|---|---|---|
| 命令 | 命令 ID、比赛/局/尝试身份、预期状态版本、动作及参数 | 鉴权、检查球权和阶段、校验值域、串行执行 |
| 命令确认 | 对应命令 ID、接受或拒绝、裁决版本、稳定原因码 | 重复命令返回相同结果；不重复执行 |
| 权威事件 | 单调事件序号、所属比赛和动作、结果、时间依据 | 驱动显示、归档和统计，不依赖回调偶然顺序 |
| 完整快照 | 状态版本、最近事件位置、当前可操作状态与显示数据 | 入房、恢复或丢失增量时使用 |

每种动作单独限定字段和范围，拒绝 NaN、Infinity、越界力度、非法触点及无权改位。未知类型、过大报文和高频请求要受限；拒绝不能部分修改比赛。

去重先识别已处理的命令，再判断新的预期版本。否则第一次已经成功、只是确认丢失的命令，会因版本已推进而被错误报告失败。同一 ID 换参数应拒绝并记录，不能把两种动作当同一次重试。

确认超时只表示客户端不知道结果，不能自行回滚或再生成一次出杆。使用原 ID 查询/重试；服务器通过持久化记录回答。具体写入次序见 [持久化](match-persistence-design.md)。

## 4. 出杆与 900 截止

现有出杆有准备、后拉、真实触球和跟杆；协议必须保留这些阶段的区别。按 Space 不是触球，准备成功也不停止 900 出杆计时。

建议先验证“服务器确认出杆计划、双方按同一权威触球时刻显示”的原型：准备时冻结合法击球参数并分配杆 ID，客户端显示受认可的动画，服务端在触球边界再次检查阶段和截止，然后施加一次冲量。没有到达有效触球边界的取消只清理准备状态，不能产生撞击声或成绩。

尚待原型决定的是：计划从服务器收到请求起计算，还是允许有界的客户端预测；往返延迟下如何让本地动画自然，以及晚到的计划如何拒绝。此处没有批准任意延迟补偿，客户端时间戳不能回填已过期的触球。

必须测量并明确以下情况后才能冻结协议：

- 正常延迟下本地球杆与母球冲量同步，对手不会看到对空气击球。
- 请求抵达时已过截止、计划触球恰在截止、触球前断线或换球权。
- 确认丢失后重试，不出现第二次冲量或声音。
- UI 倒计时与权威时钟允许显示平滑，但错误显示不能获得额外时间。

## 5. 球运动与本地显示

服务端固定步长推进物理，真实比赛时钟单独推进。网络广播频率、物理步长和浏览器渲染频率不要求相同；频率与带宽预算通过原型测量，不在文档猜一个数当承诺。

同步包括球位置、姿态、活跃状态、必要速度与有序撞击/规则事件。客户端使用插值；如加入预测，也必须可校正并标明状态版本。落袋、自转、辅助线和声音要有明确来源，不能靠客户端重算另一份裁判结果。

镜头、音量、菜单展开与悬停候选点留在本地。玩家对实际摆球的提交才是权威命令；不广播每次鼠标移动来改变对手的真实球位。

局面稳定时发送可核对检查点；发现版本缺口请求重同步。不能把不同回合的运动帧混合插值，也不能用旧快照覆盖较新终局。

## 6. 重连与同步恢复

重连认证仍使用原账号与席位，服务器返回当前生命周期状态、检查点及必要后续事件。客户端丢弃旧输入、未生效的本地动画和 AI 缓存，再根据真实阶段重建操作能力。

期间已发生的超时、进球和终局以服务器为准。不要重播所有历史声音来“补齐”，也不要因为收到历史触球事件再次施加物理冲量。

持久化的比赛版本、每连接的投递位置和临时视觉帧编号用途不同，不共用一个字段。事件补发可以重复，应用效果必须幂等；保存期限由数据设计决定，不假定所有视觉帧永久可补。

## 7. 对外依赖

账号服务只提供身份与权限；统计、高光通过已提交的对局事实处理。排行榜或媒体任务失败不阻塞裁决。语音与游戏指令分通道，范围见 [语音设计](voice-design.md)。

未来桌面客户端复用同一协议，不能把 DOM、浏览器 localStorage 或相机对象作为服务端必需状态。

## 8. 冻结前验收

两个独立客户端测试正常击球、重复/乱序/越权请求、弱网、连接接管和恢复；两个同时运行的房间验证共享状态隔离。900 另验证触球/截止竞争。未完成这些实验前，本文仍是提案，不能以写了报文类型宣称联机可交付。
